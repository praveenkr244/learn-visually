Basics

Why TypeScript?

TypeScript adds type annotations to JavaScript. The TypeScript compiler (tsc) checks that values are used consistently, reports mistakes as you type, then erases the types and outputs plain JavaScript. At run time there is no TypeScript at all, only the JavaScript it produced.

// In JavaScript this bug only shows up when the code runs:
function total(prices: number[]): number {
  return prices.reduce((sum, p) => sum + p, 0);
}

console.log(total([4.5, 10, 2]));

// Uncomment the next line and press Run: TypeScript stops it before it runs.
// console.log(total(["4.5", "10"]));
// A typo JavaScript would happily run (printing undefined):
const user = { firstName: "Ada", lastName: "Lovelace" };
console.log(user.firstname);

Basic types and inference

Annotate a variable with : type. Most of the time you don't need to: TypeScript infers the type from the value. The basic types match JavaScript's: string, number, boolean, bigint, symbol, null, undefined, plus special ones like any, unknown, void and never.

let title: string = "Report";   // explicit annotation
let pages = 12;                 // inferred: number
const ready = true;             // inferred: true (a literal type)

pages = 13;                     // fine
// pages = "thirteen";          // error: string is not assignable to number

let big: bigint = 10n ** 20n;
let id: number | string = 42;   // a union: either type
id = "A-42";

console.log(title, pages, ready, big, id);

// Annotate when there is no initial value
let answer: number;
answer = 42;
console.log(answer);

Arrays, tuples and object types

Arrays are written string[] (or Array<string>). Tuples are fixed-length arrays where each position has its own type: [string, number]. Object types list their properties: { name: string; age?: number }, where ? marks an optional property and readonly one you can't reassign.

const tags: string[] = ["ts", "js"];
const matrix: number[][] = [[1, 2], [3, 4]];
tags.push("web");
// tags.push(42);               // error: number is not assignable to string

// Tuple: position matters
const point: [number, number] = [10, 20];
const entry: [name: string, score: number] = ["Ada", 95];   // labelled tuple
const [who, score] = entry;
console.log(tags, matrix[1][0], point[0] + point[1], who, score);

// readonly arrays can't be changed
const days: readonly string[] = ["Mon", "Tue"];
// days.push("Wed");            // error: push does not exist on readonly string[]
console.log(days.length);
// An object type written inline
let product: { readonly id: number; name: string; price: number; discount?: number } = {
  id: 1,
  name: "Lamp",
  price: 45,
};

product.price = 40;             // fine
// product.id = 2;              // error: id is read-only
// product.colour = "red";      // error: colour does not exist (did you mean...?)

// Optional properties may be undefined: handle that case
const finalPrice = product.price - (product.discount ?? 0);
console.log(product, finalPrice);

// Index signature: any string key, number values
const stock: { [sku: string]: number } = { A1: 3, B2: 0 };
stock.C3 = 12;
console.log(stock);
Check yourself

  2. What does age?: number mean? — age may be missing, so its type is number | undefined.

Typing functions

Annotate each parameter; the return type is usually inferred, but writing it makes your intent explicit and catches mistakes inside the function. Optional parameters use ?, defaults use =, rest parameters are typed arrays, and a function type looks like (a: number) => string.

function area(width: number, height: number): number {
  return width * height;
}

// Optional and default parameters
function greet(name: string, greeting = "Hello", punctuation?: string): string {
  return `${greeting}, ${name}${punctuation ?? "!"}`;
}

// Rest parameters
function sum(...nums: number[]): number {
  return nums.reduce((a, b) => a + b, 0);
}

// Arrow function with types
const toCelsius = (f: number): number => ((f - 32) * 5) / 9;

console.log(area(3, 4), greet("Ada"), greet("Linus", "Hi", "?"), sum(1, 2, 3), toCelsius(212));
// area(3);                     // error: Expected 2 arguments, but got 1
// Function types: describe a function's shape
type Operation = (a: number, b: number) => number;

const add: Operation = (a, b) => a + b;   // parameters inferred from the type
const mul: Operation = (a, b) => a * b;

function applyAll(ops: Operation[], a: number, b: number): number[] {
  return ops.map(op => op(a, b));
}
console.log(applyAll([add, mul, Math.max], 6, 7));

// Callbacks are checked too
const words = ["delta", "alpha", "charlie"];
words.sort((x, y) => x.localeCompare(y));
console.log(words);
// Overloads: several call signatures, one implementation
function format(value: number): string;
function format(value: Date): string;
function format(value: number | Date): string {
  return typeof value === "number" ? value.toFixed(2) : value.toISOString().slice(0, 10);
}
console.log(format(3.14159), format(new Date(Date.UTC(2026, 10, 25))));
Check yourself
  1. Where must optional parameters go? — After all required ones.
  2. What does type Fn = (x: string) => void describe? — A function taking one string and returning nothing useful.

Interfaces and type aliases

Give an object shape a name so you can reuse it. interface User { … } and type User = { … } are nearly interchangeable for objects. Interfaces can extend each other; type aliases can name any type, including unions and tuples.

interface Address {
  street: string;
  city: string;
}

interface User {
  readonly id: number;
  name: string;
  email?: string;
  address: Address;
}

// extends: everything in User plus more
interface Admin extends User {
  permissions: string[];
}

const admin: Admin = {
  id: 1,
  name: "Ada",
  address: { street: "1 Main St", city: "London" },
  permissions: ["delete-users"],
};

function describe(user: User): string {
  return `${user.name} from ${user.address.city}${user.email ? ` <${user.email}>` : ""}`;
}
console.log(describe(admin));     // an Admin is also a User
// type aliases name any type
type ID = number | string;
type Point = { x: number; y: number };
type Pair = [Point, Point];
type Callback = (error: Error | null, data?: string) => void;

// & (intersection) combines object types
type Timestamped = { createdAt: Date };
type Post = { title: string } & Timestamped;

const ids: ID[] = [1, "a2"];
const line: Pair = [{ x: 0, y: 0 }, { x: 3, y: 4 }];
const post: Post = { title: "Hello", createdAt: new Date(0) };
const cb: Callback = (err, data) => console.log(err?.message ?? data);

const length = Math.hypot(line[1].x - line[0].x, line[1].y - line[0].y);
console.log(ids, length, post.title);
cb(null, "callback ok");

Union and literal types

A union A | B means "either A or B". A literal type is one exact value, like "small" or 42. Together they describe a fixed set of allowed values, which is clearer and safer than a plain string.

type Size = "small" | "medium" | "large";
type Status = 200 | 404 | 500;

function price(size: Size): number {
  switch (size) {
    case "small": return 2;
    case "medium": return 3;
    case "large": return 4;
  }
}

console.log(price("medium"));
// price("huge");                // error: "huge" is not assignable to type Size

let code: Status = 404;
console.log(code);

// A union of different types
function formatId(id: number | string): string {
  // Only methods that exist on BOTH types are allowed until you check which one it is
  return typeof id === "number" ? `#${id.toString().padStart(4, "0")}` : id.toUpperCase();
}
console.log(formatId(42), formatId("ab-7"));
// Literal types are inferred for const, widened for let
const direction = "left";        // type "left"
let heading = "left";            // type string

type Direction = "left" | "right" | "up" | "down";
function move(d: Direction, steps = 1) {
  return `${d} × ${steps}`;
}
console.log(move(direction));
// console.log(move(heading));   // error: string is not assignable to Direction

// Union of objects: only shared properties are accessible directly
type Cat = { kind: "cat"; meows: boolean };
type Dog = { kind: "dog"; barks: boolean };
const pet: Cat | Dog = { kind: "dog", barks: true };
console.log(pet.kind);           // fine: both have kind
Check yourself
  1. What values does type Bit = 0 | 1 allow? — Only the numbers 0 and 1.
  2. On a value of type string | number, can you call .toUpperCase() directly? — No, only after narrowing to string.

Narrowing

Inside an if, TypeScript follows your checks and narrows a wide type to a more specific one. typeof, instanceof, in, equality checks, truthiness and early returns all narrow. After narrowing you can use the specific type's methods safely.

function describe(value: string | number | boolean | null | Date | string[]): string {
  if (value === null) return "nothing";                     // value: null
  if (typeof value === "string") return `text of ${value.length}`;   // value: string
  if (typeof value === "number") return value.toFixed(1);   // value: number
  if (typeof value === "boolean") return value ? "yes" : "no";
  if (value instanceof Date) return value.getUTCFullYear().toString();   // value: Date
  return value.join("+");                                    // only string[] is left
}

for (const v of ["hi", 3.14159, true, null, new Date(Date.UTC(2026, 0, 1)), ["a", "b"]]) {
  console.log(describe(v));
}
// "in" narrows by checking for a property
type Fish = { swim: () => string };
type Bird = { fly: () => string };

function move(animal: Fish | Bird): string {
  if ("swim" in animal) return animal.swim();   // Fish
  return animal.fly();                          // Bird
}
console.log(move({ swim: () => "splash" }), move({ fly: () => "flap" }));

// Truthiness narrowing removes null and undefined
function initials(name?: string | null): string {
  if (!name) return "?";
  return name.split(" ").map(w => w[0]).join("");  // name: string here
}
console.log(initials("Grace Hopper"), initials(undefined), initials(""));
Check yourself
  1. Which check narrows to a class instance? — instanceof.
  2. After if (typeof x === "string") return;, what is x? — Whatever was left in the union without string.

Practice: two more runnable examples

  return Array.isArray(input) ? input : input.split(",").map(s => s.trim());
}

// Narrowing inside a loop over a union array

  if (v === undefined) continue;
  total += typeof v === "string" ? Number(v) : v;
}
console.log(total);

Enums, as const and literal unions

An enum gives names to a set of constants. Enums are one of the few TypeScript features that produce real JavaScript (press JS to see). Many teams prefer a union of string literals or an object marked as const, which give the same safety with plain JavaScript.

enum Direction {
  Up,          // 0
  Down,        // 1
  Left,        // 2
  Right,       // 3
}

enum Role {
  Admin = "ADMIN",
  Editor = "EDITOR",
  Viewer = "VIEWER",
}

function canEdit(role: Role): boolean {
  return role === Role.Admin || role === Role.Editor;
}

console.log(Direction.Left, Direction[2]);   // numeric enums map both ways
console.log(Role.Editor, canEdit(Role.Viewer), canEdit(Role.Admin));
// as const: the most precise, read-only types
const ROLES = ["admin", "editor", "viewer"] as const;   // readonly ["admin", "editor", "viewer"]
type Role = (typeof ROLES)[number];                     // "admin" | "editor" | "viewer"

const COLORS = { primary: "#3178c6", danger: "#e03131" } as const;
type ColorName = keyof typeof COLORS;                   // "primary" | "danger"

function badge(role: Role, color: ColorName): string {
  return `${role.toUpperCase()} in ${COLORS[color]}`;
}
console.log(badge("editor", "primary"));
console.log(ROLES.includes("viewer"));
// COLORS.primary = "red";      // error: read-only
Check yourself
  1. What does as const do to an array literal? — Makes it a readonly tuple of literal types.
  2. Do enums disappear when compiled? — No, regular enums become a JavaScript object.

Classes in TypeScript

TypeScript types class fields and adds access modifiers: public (default), private and protected (checked at compile time), plus readonly. Parameter properties declare and assign fields straight from the constructor. A class can implements an interface to promise it has a certain shape, and abstract classes leave methods for subclasses to fill in.

interface Account {
  readonly owner: string;
  balance(): number;
}

class BankAccount implements Account {
  private history: number[] = [];
  static readonly MIN = 0;

  // parameter properties: declare + assign in one place
  constructor(public readonly owner: string, private amount = 0) {}

  deposit(value: number): this {
    if (value <= 0) throw new RangeError("Deposit must be positive");
    this.amount += value;
    this.history.push(value);
    return this;
  }
  balance(): number {
    return this.amount;
  }
}

const acc = new BankAccount("Ada").deposit(50).deposit(25);
console.log(acc.owner, acc.balance());
// acc.amount = 1e6;             // error: 'amount' is private
// acc.owner = "Eve";            // error: owner is read-only
abstract class Shape {
  constructor(protected readonly name: string) {}
  abstract area(): number;                       // subclasses must implement
  describe(): string {
    return `${this.name} with area ${this.area().toFixed(2)}`;
  }
}

class Circle extends Shape {
  constructor(private r: number) { super("circle"); }
  area() { return Math.PI * this.r ** 2; }
}
class Rect extends Shape {
  constructor(private w: number, private h: number) { super("rectangle"); }
  area() { return this.w * this.h; }
}

const shapes: Shape[] = [new Circle(1), new Rect(2, 3)];
shapes.forEach(s => console.log(s.describe()));
// new Shape("x");               // error: cannot create an instance of an abstract class
private vs #private

TypeScript's private is checked only by the compiler; the field is still visible at run time. JavaScript's #field is truly private at run time too. Both work in TypeScript.

Check yourself
  1. What does constructor(private x: number) {} do? — Declares a private field x and assigns the argument to it.
  2. What does implements check? — That the class has every member the interface requires.

Generics

A generic is a type parameter, a placeholder like T that gets filled in when the code is used. function first<T>(items: T[]): T | undefined works for any array and still knows that the result has the same type as the items. Generics are how Array<T>, Promise<T> and Map<K, V> work.

function first<T>(items: T[]): T | undefined {
  return items[0];
}
const n = first([10, 20]);        // T = number   → number | undefined
const s = first(["a", "b"]);      // T = string   → string | undefined
console.log(n, s?.toUpperCase());

// Several type parameters
function pair<A, B>(a: A, b: B): [A, B] {
  return [a, b];
}
const p = pair("age", 36);        // [string, number]
console.log(p);

// Generic interfaces and classes
interface Box<T> { value: T; label: string }
const numberBox: Box<number> = { value: 42, label: "answer" };

class Queue<T> {
  private items: T[] = [];
  enqueue(item: T) { this.items.push(item); }
  dequeue(): T | undefined { return this.items.shift(); }
  get length() { return this.items.length; }
}
const q = new Queue<string>();
q.enqueue("first"); q.enqueue("second");
// q.enqueue(3);                  // error: number is not assignable to string
console.log(numberBox, q.dequeue(), q.length);

Constraints: T must have something

// extends limits what T can be, so you can use its properties
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}
console.log(longest("apple", "kiwi"), longest([1, 2, 3], [4]));
// longest(10, 20);               // error: number has no length

// keyof constraint: K must be one of T's keys
function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {
  return items.map(item => item[key]);
}
const users = [{ name: "Ada", age: 36 }, { name: "Linus", age: 54 }];
console.log(pluck(users, "name"), pluck(users, "age"));
// pluck(users, "email");         // error: "email" is not a key

// Default type parameters
interface ApiResult<T = unknown> { ok: boolean; data: T }
const r: ApiResult<string[]> = { ok: true, data: ["x"] };
console.log(r.data.length);

  1. Why not write first(items: any[]): any? — You'd lose the link between input and output types.
  2. What does T extends { length: number } mean? — T can be any type that has a numeric length property.

// A typed cache that remembers results of an async loader
class Cache<K, V> {
  private store = new Map<K, V>();
  constructor(private load: (key: K) => V) {}
  get(key: K): V {
    if (!this.store.has(key)) this.store.set(key, this.load(key));
    return this.store.get(key)!;
  }
}

Structural typing

TypeScript compares types by their shape, not their name. If a value has all the properties a type requires (with compatible types), it fits, even if it was never declared as that type and has extra properties. This is sometimes called "duck typing, checked at compile time".

interface Point { x: number; y: number }

function distance(p: Point): number {
  return Math.hypot(p.x, p.y);
}

class Vector { constructor(public x: number, public y: number, public z = 0) {} }
const fromJson = JSON.parse('{"x": 3, "y": 4}') as Point;
const location3d = { x: 3, y: 4, z: 12, label: "peak" };

console.log(distance(new Vector(3, 4)));    // a class with the right shape fits
console.log(distance(fromJson));
console.log(distance(location3d));          // extra properties are fine for variables…
// distance({ x: 3, y: 4, z: 12 });        // …but not in an object literal written inline (excess property check)
Excess property checks

When you pass an object literal directly, TypeScript flags unknown properties, because that is almost always a typo. A variable holding the same object passes, because it may legitimately be used elsewhere with more fields.

// Functions are compared by parameters and return type too

const noArgs: Handler = () => console.log("called");          // fewer parameters: fine

Discriminated unions

Give each member of a union a shared literal property, the discriminant (often kind or type). Checking it narrows to exactly one member. Add a never check in the default case and the compiler tells you every place to update when you add a new member. This is the most useful pattern in TypeScript.

type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number }
  | { kind: "rect"; width: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle": return Math.PI * shape.radius ** 2;   // shape is the circle member here
    case "square": return shape.side ** 2;
    case "rect": return shape.width * shape.height;
    default: {
      const unreachable: never = shape;                  // fails to compile if a case is missing
      return unreachable;
    }
  }
}

const shapes: Shape[] = [{ kind: "circle", radius: 1 }, { kind: "square", side: 2 }, { kind: "rect", width: 2, height: 5 }];
console.log(shapes.map(area).map(a => a.toFixed(2)));
// Now add  | { kind: "triangle"; base: number; height: number }  to Shape and Run.
// Model states that can't be mixed up: no "loading AND error"

unknown, type guards and assertions

Data from outside your program (JSON, user input, catch blocks) has no trustworthy type. Type it as unknown and check it. A type guard (x is T) packages a check so it narrows wherever you call it; an assertion function (asserts x is T) throws if the check fails. Avoid as casts: they tell the compiler to trust you without checking anything.

interface User { name: string; age: number }

// A type guard: returns boolean, but narrows the caller's variable
function isUser(value: unknown): value is User {
  return (
    typeof value === "object" && value !== null &&
    "name" in value && typeof value.name === "string" &&
    "age" in value && typeof value.age === "number"
  );
}

const inputs: unknown[] = [
  JSON.parse('{"name": "Ada", "age": 36}'),
  JSON.parse('{"name": "Bob"}'),
  "just a string",
];

for (const data of inputs) {
  if (isUser(data)) console.log(`✓ ${data.name} is ${data.age}`);   // data: User
  else console.log("✗ not a user:", data);
}
// Assertion functions throw instead of returning false
interface User { name: string; age: number }

function assertIsString(value: unknown, name: string): asserts value is string {
  if (typeof value !== "string") throw new TypeError(`${name} must be a string, got ${typeof value}`);
}

function shout(input: unknown) {
  assertIsString(input, "input");
  return input.toUpperCase();        // input: string after the assertion
}
console.log(shout("hey"));

// catch variables are unknown: check before using
try {
  shout(42);
} catch (err) {
  if (err instanceof Error) console.log(err.name, "→", err.message);
}

// "as" only silences the compiler. This compiles and is still wrong:
const fake = JSON.parse('{"nme": "typo"}') as User;
console.log(fake.name);   // undefined at run time!
Check yourself

  2. Does x as User check anything at run time? — No, it's erased; it only changes what the compiler believes.

null, undefined and strict checks

With strict mode on (always use it), null and undefined are separate types. A value that might be missing must say so (string | undefined), and TypeScript makes you handle that case before using it. That removes the most common JavaScript crash: "cannot read properties of undefined".

const users = [{ id: 1, name: "Ada", manager: { name: "Babbage" } }, { id: 2, name: "Linus" }];

const found = users.find(u => u.id === 2);   // type includes undefined
// console.log(found.name);                   // error: 'found' is possibly 'undefined'

// Ways to handle it:
if (found) console.log(found.name);                          // 1. narrow with if
console.log(found?.name ?? "nobody");                        // 2. ?. and ??
const managerName = users[0].manager?.name ?? "no manager";  // 3. optional chaining deeper
console.log(managerName);

// 4. The non-null assertion ! says "trust me, it's there". Use rarely.
const ada = users.find(u => u.id === 1)!;
console.log(ada.name);

// Optional parameters are T | undefined
function greet(name?: string) {
  return `Hi ${name?.trim() || "there"}`;
}
console.log(greet(), greet("  Grace "));
// noUncheckedIndexedAccess (a stricter flag) treats arr[i] as possibly undefined.
// Even without it, prefer methods that admit "might be missing":
const queue: string[] = [];
const next = queue.shift();        // string | undefined
console.log(next ?? "queue empty");

const scores = new Map<string, number>();
scores.set("ada", 3);
const current = scores.get("linus") ?? 0;   // Map.get is T | undefined
scores.set("linus", current + 1);
console.log([...scores]);

Async code and typed APIs

An async function returning T has the type Promise<T>, and await unwraps it. The catch with APIs: res.json() returns any, because TypeScript can't know what a server sends. Declare the shape you expect and, for anything important, validate it at run time.

  return res.json() as Promise<T>;   // a promise you make: the server is trusted here
}

// Validate untrusted data and return a Result instead of throwing
type Result<T> = { ok: true; value: T } | { ok: false; error: string };
interface Post { id: number; title: string }

function parsePost(data: unknown): Result<Post> {
  if (typeof data !== "object" || data === null) return { ok: false, error: "not an object" };
  const d = data as Record<string, unknown>;
  if (typeof d.id !== "number") return { ok: false, error: "id must be a number" };
  if (typeof d.title !== "string") return { ok: false, error: "title must be a string" };
  return { ok: true, value: { id: d.id, title: d.title } };
}

keyof, typeof and indexed access

Types can be computed from other types and from values. keyof T is the union of T's keys. typeof value (in a type position) gives the type of a value. T["key"] looks up the type of one property. Together they keep types in sync with your data automatically.

interface User { id: number; name: string; active: boolean }

type UserKey = keyof User;               // "id" | "name" | "active"
type NameType = User["name"];            // string
type IdOrName = User["id" | "name"];     // number | string

// A type-safe getter: the return type follows the key
function get<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
const u: User = { id: 1, name: "Ada", active: true };
const n = get(u, "name");                // string
const a = get(u, "active");              // boolean
console.log(n.toUpperCase(), a);
// get(u, "email");                      // error: not a key of User

// typeof: get a type FROM a value
const defaults = { theme: "light", fontSize: 14, sound: true };
type Settings = typeof defaults;         // { theme: string; fontSize: number; sound: boolean }
function applySettings(s: Partial<Settings>): Settings {
  return { ...defaults, ...s };
}
console.log(applySettings({ fontSize: 18 }));
// Element types of arrays and tuples
const palette = ["red", "green", "blue"] as const;
type Color = (typeof palette)[number];   // "red" | "green" | "blue"

const routes = {
  home: "/",
  profile: "/user/:id",
  settings: "/settings",

}

Mapped types

A mapped type builds a new object type by looping over keys: { [K in keyof T]: … }. It's how Partial, Readonly and Record are written. You can add or remove ? and readonly, change each property's type, and even rename keys with as.

interface Product { name: string; price: number; inStock: boolean }

// Rebuild Partial and Readonly yourself
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyReadonly<T> = { readonly [K in keyof T]: T[K] };
type Mutable<T> = { -readonly [K in keyof T]: T[K] };     // "-" removes a modifier

// Change every property's type
type Flags<T> = { [K in keyof T]: boolean };
type Validators<T> = { [K in keyof T]: (value: T[K]) => string | null };

const touched: Flags<Product> = { name: true, price: false, inStock: false };
const rules: Validators<Product> = {
  name: v => (v.trim() ? null : "Name is required"),
  price: v => (v > 0 ? null : "Price must be positive"),
  inStock: () => null,
};

const draft: MyPartial<Product> = { price: -3 };
const p: Product = { name: "", price: -3, inStock: true };
const errors = (Object.keys(rules) as (keyof Product)[])
  .map(k => [k, (rules[k] as (v: unknown) => string | null)(p[k])] as const)
  .filter(([, msg]) => msg !== null);
console.log(touched, draft, errors);
// Key remapping with "as" and template literal types
interface State { count: number; label: string }

type Setters<T> = { [K in keyof T as `set${Capitalize<string & K>}`]: (value: T[K]) => void };

function createStore(initial: State): Getters<State> & Setters<State> {

    setLabel: v => { state = { ...state, label: v }; },

}

Conditional types and infer

A conditional type chooses between two types: T extends U ? X : Y. Applied to a union it runs once per member (distributive). Inside the condition, infer captures part of a type into a new name, which is how ReturnType, Awaited and Parameters are built.

type IsString<T> = T extends string ? "yes" : "no";
type A = IsString<"hi">;          // "yes"
type B = IsString<42>;            // "no"

// Distributive: runs per union member
type NonNull<T> = T extends null | undefined ? never : T;
type C = NonNull<string | null | number | undefined>;   // string | number

// infer: pull a type out
type ElementOf<T> = T extends (infer E)[] ? E : never;
type MyReturn<F> = F extends (...args: any[]) => infer R ? R : never;
type Unpromise<T> = T extends Promise<infer V> ? V : T;

type D = ElementOf<string[]>;                    // string
type E = MyReturn<(x: number) => boolean>;       // boolean
type F = Unpromise<Promise<{ ok: true }>>;       // { ok: true }

const a: A = "yes", b: B = "no", c: C[] = ["text", 7], d: D = "item", e: E = true, f: F = { ok: true };
console.log(a, b, c, d, e, f);
// const wrong: B = "yes";        // error: "yes" is not assignable to "no"
// A practical one: the type of an event's payload, looked up by name
type Events = {
  login: { user: string };
  logout: undefined;
  purchase: { amount: number; currency: "USD" | "EUR" };
};

// Events whose payload is undefined take no argument
type EmitArgs<K extends keyof Events> = Events[K] extends undefined ? [] : [payload: Events[K]];

function emit<K extends keyof Events>(name: K, ...args: EmitArgs<K>): void {
  console.log(`emit ${name}`, ...args);
}

// emit("logout", {});            // error: expected 1 argument
// emit("purchase", { amount: 9.5 });   // error: currency is missing

Type-safe patterns

A few patterns make whole classes of bugs impossible: satisfies checks a value against a type without widening it; branded types stop you mixing up values with the same underlying type (user ids vs order ids); const type parameters keep literal types; and builders track what's been set in the type itself.

  2. Write small, typed functions

  if (score >= 80) return "B";
  if (score >= 70) return "C";
  if (score >= 60) return "D";
  return "F";
}

  let best: Subject = SUBJECTS[0], worst: Subject = SUBJECTS[0];
  for (const s of SUBJECTS) {
    if (scores[s] > scores[best]) best = s;
    if (scores[s] < scores[worst]) worst = s;

    A ReportCard type describes the output; reportCard() builds one per student and classStats() uses a mapped object over subjects. console.table prints the results.

    const SUBJECTS = ["math", "science", "english", "history"] as const;
type Subject = (typeof SUBJECTS)[number];
type Letter = "A" | "B" | "C" | "D" | "F";

interface Student { id: number; name: string; scores: Record<Subject, number> }

interface ReportCard {
  name: string;
  average: number;
  letter: Letter;
  best: Subject;
  worst: Subject;
}

interface SubjectStats { average: number; top: string; failing: number }

const average = (nums: readonly number[]): number =>
  nums.length ? nums.reduce((a, b) => a + b, 0) / nums.length : 0;

const round1 = (n: number) => Math.round(n * 10) / 10;

function letter(score: number): Letter {
  if (score >= 90) return "A";
  if (score >= 80) return "B";
  if (score >= 70) return "C";
  if (score >= 60) return "D";
  return "F";
}

function reportCard(student: Student): ReportCard {
  const values = SUBJECTS.map(s => student.scores[s]);
  const avg = average(values);
  const sorted = [...SUBJECTS].sort((a, b) => student.scores[b] - student.scores[a]);
  return { name: student.name, average: round1(avg), letter: letter(avg), best: sorted[0], worst: sorted[sorted.length - 1] };
}

function classStats(students: Student[]): Record<Subject, SubjectStats> {
  const stats = {} as Record<Subject, SubjectStats>;
  for (const subject of SUBJECTS) {
    const top = students.reduce((a, b) => (b.scores[subject] > a.scores[subject] ? b : a));
    stats[subject] = {
      average: round1(average(students.map(s => s.scores[subject]))),
      top: top.name,
      failing: students.filter(s => s.scores[subject] < 60).length,
    };
  }
  return stats;
}

How the code works

  • (typeof SUBJECTS)[number] Turns the array into a union type. The list is the single source of truth for both the loops (values) and the checks (types).
  • Record<Subject, number> Forces a score for every subject. Add "art" to SUBJECTS and the compiler points at every student that lacks it.
  • function letter(score: number): Letter The declared return type is checked against every return, so an invalid grade can't slip out.
  • {} as Record<Subject, SubjectStats> The object starts empty and the loop fills every key. as is acceptable here because the very next lines make it true; keep casts this local.
  • [...SUBJECTS].sort(...) SUBJECTS is readonly, so it's copied before sorting. TypeScript would reject SUBJECTS.sort().

Model a small bank: accounts with private balances, a typed transaction history, and transfers between accounts. Instead of throwing for expected problems (not enough money, frozen account), every operation returns a Result that the compiler forces callers to check.

Build it step by step

  1. Design the Result and error types

    A Result<T, E> is either success with a value or failure with an error. Each error is a member of a discriminated union with its own data, so a caller can show "you need $12.50 more" instead of a vague message.

    type Result<T, E> = { ok: true; value: T } | { ok: false; error: E };
const ok = <T>(value: T): Result<T, never> => ({ ok: true, value });
const err = <E>(error: E): Result<never, E> => ({ ok: false, error });

type BankError =
  | { code: "INVALID_AMOUNT"; amount: number }
  | { code: "INSUFFICIENT_FUNDS"; balance: number; requested: number }
  | { code: "ACCOUNT_FROZEN"; accountId: string }
  | { code: "NOT_FOUND"; accountId: string };

function explain(e: BankError): string {
  switch (e.code) {
    case "INVALID_AMOUNT": return `Amount must be positive (got ${e.amount})`;
    case "INSUFFICIENT_FUNDS": return `Not enough money: need ${e.requested - e.balance} more cents`;
    case "ACCOUNT_FROZEN": return `Account ${e.accountId} is frozen`;
    case "NOT_FOUND": return `No account ${e.accountId}`;
  }
}

  2. The Account class

    The balance is a #private field in cents: no code outside the class can change it, at compile time or run time. Every change goes through a method that validates first and records a Transaction.

    type Result<T, E> = { ok: true; value: T } | { ok: false; error: E };
type BankError = { code: "INVALID_AMOUNT"; amount: number } | { code: "INSUFFICIENT_FUNDS"; balance: number; requested: number };
interface Transaction { kind: "deposit" | "withdrawal"; cents: number; balanceAfter: number }

class Account {
  #balance = 0;
  readonly history: Transaction[] = [];
  constructor(readonly id: string, readonly owner: string) {}

  get balance(): number { return this.#balance; }

  deposit(cents: number): Result<number, BankError> {
    if (!Number.isInteger(cents) || cents <= 0) return { ok: false, error: { code: "INVALID_AMOUNT", amount: cents } };
    this.#balance += cents;
    this.history.push({ kind: "deposit", cents, balanceAfter: this.#balance });
    return { ok: true, value: this.#balance };
  }

  withdraw(cents: number): Result<number, BankError> {
    if (!Number.isInteger(cents) || cents <= 0) return { ok: false, error: { code: "INVALID_AMOUNT", amount: cents } };
    if (cents > this.#balance) return { ok: false, error: { code: "INSUFFICIENT_FUNDS", balance: this.#balance, requested: cents } };
    this.#balance -= cents;
    this.history.push({ kind: "withdrawal", cents, balanceAfter: this.#balance });
    return { ok: true, value: this.#balance };
  }
}

class Account {
  #balance = 0;
  #frozen = false;
  readonly history: Transaction[] = [];
  constructor(readonly id: string, readonly owner: string) {}

  get balance() { return this.#balance; }
  freeze() { this.#frozen = true; }

  #check(cents: number): BankError | null {
    if (this.#frozen) return { code: "ACCOUNT_FROZEN", accountId: this.id };
    if (!Number.isInteger(cents) || cents <= 0) return { code: "INVALID_AMOUNT", amount: cents };
    return null;
  }

  deposit(cents: number, kind: "deposit" | "transfer-in" = "deposit", note?: string): Result<number, BankError> {
    const problem = this.#check(cents);
    if (problem) return fail(problem);
    this.#balance += cents;
    this.history.push({ kind, cents, balanceAfter: this.#balance, note });
    return ok(this.#balance);
  }

  withdraw(cents: number, kind: "withdrawal" | "transfer-out" = "withdrawal", note?: string): Result<number, BankError> {
    const problem = this.#check(cents);
    if (problem) return fail(problem);
    if (cents > this.#balance) return fail({ code: "INSUFFICIENT_FUNDS", balance: this.#balance, requested: cents });
    this.#balance -= cents;
    this.history.push({ kind, cents, balanceAfter: this.#balance, note });
    return ok(this.#balance);
  }
}

class Bank {
  private accounts = new Map<string, Account>();
  private nextId = 1;

  open(owner: string, initialCents = 0): Account {
    const account = new Account(`ACC-${String(this.nextId++).padStart(3, "0")}`, owner);
    if (initialCents > 0) account.deposit(initialCents);
    this.accounts.set(account.id, account);
    return account;
  }

  find(id: string): Result<Account, BankError> {
    const account = this.accounts.get(id);
    return account ? ok(account) : fail({ code: "NOT_FOUND", accountId: id });
  }

  transfer(fromId: string, toId: string, cents: number): Result<string, BankError> {
    const from = this.find(fromId);
    if (!from.ok) return from;
    const to = this.find(toId);
    if (!to.ok) return to;

    const out = from.value.withdraw(cents, "transfer-out", `to ${to.value.owner}`);
    if (!out.ok) return out;
    const inn = to.value.deposit(cents, "transfer-in", `from ${from.value.owner}`);
    if (!inn.ok) {
      from.value.deposit(cents, "deposit", "refund: transfer failed");   // roll back
      return inn;
    }
    return ok(`Sent ${fmt(cents)} from ${from.value.owner} to ${to.value.owner}`);
  }

  statement(id: string): string {
    const found = this.find(id);
    if (!found.ok) return explain(found.error);
    const a = found.value;
    const lines = a.history.map(t => {
      const sign = t.kind === "deposit" || t.kind === "transfer-in" ? "+" : "-";
      return `  ${t.kind.padEnd(12)} ${(sign + fmt(t.cents)).padStart(11)}  ${fmt(t.balanceAfter).padStart(10)}  ${t.note ?? ""}`;
    });
    return [`${a.id} · ${a.owner}`, ...lines, `  balance: ${fmt(a.balance)}`].join("\n");
  }
}

function explain(e: BankError): string {
  switch (e.code) {
    case "INVALID_AMOUNT": return `✗ Amount must be a positive number of cents (got ${e.amount})`;
    case "INSUFFICIENT_FUNDS": return `✗ Not enough money: balance ${fmt(e.balance)}, requested ${fmt(e.requested)}`;
    case "ACCOUNT_FROZEN": return `✗ Account ${e.accountId} is frozen`;
    case "NOT_FOUND": return `✗ No account called ${e.accountId}`;
  }
}

    createStore is generic over any state S and action A, so the same code works for a to-do app, a shopping cart or a game. Middleware wraps dispatch (here: a logger), and selectors compute derived data from the state.

    // ---------- a generic store, reusable for any app ----------
type Reducer<S, A> = (state: S, action: A) => S;
type Listener<S> = (state: S) => void;
type Middleware<S, A> = (store: { getState: () => S }) => (next: (a: A) => void) => (action: A) => void;

interface Store<S, A> {
  getState(): S;
  dispatch(action: A): void;
  subscribe(listener: Listener<S>): () => void;
}

function createStore<S, A>(reducer: Reducer<S, A>, initial: S, middleware: Middleware<S, A>[] = []): Store<S, A> {
  let state = initial;
  const listeners = new Set<Listener<S>>();
  const getState = () => state;
  const baseDispatch = (action: A) => {
    state = reducer(state, action);
    listeners.forEach(l => l(state));
  };
  const dispatch = middleware.reduceRight<(a: A) => void>((next, mw) => mw({ getState })(next), baseDispatch);
  return {
    getState,
    dispatch,
    subscribe(listener) {
      listeners.add(listener);
      return () => { listeners.delete(listener); };
    },
  };
}

    type Result<T> = { ok: true; value: T } | { ok: false; errors: string[] };
interface Schema<T> { parse(input: unknown, path: string): Result<T>; optional(): Schema<T | undefined> }

function makeSchema<T>(parse: (input: unknown, path: string) => Result<T>): Schema<T> {
  return {
    parse,
    optional: () => makeSchema<T | undefined>((input, path) => (input === undefined || input === "" ? ok(undefined) : parse(input, path))),
  };
}

  3. The finished validator

    s.object(shape) runs every field's schema, collects all errors, and its type is a mapped type over the shape: { [K in keyof Shape]: Infer<Shape[K]> }. Declare a sign-up schema, then type SignUp = Infer<typeof signUpSchema> is the exact type of valid data.

    type Result<T> = { ok: true; value: T } | { ok: false; errors: string[] };
interface Schema<T> { parse(input: unknown, path: string): Result<T>; optional(): Schema<T | undefined> }
type Infer<S> = S extends Schema<infer T> ? T : never;

const ok = <T>(value: T): Result<T> => ({ ok: true, value });
const fail = (message: string): Result<never> => ({ ok: false, errors: [message] });

function makeSchema<T>(parse: (input: unknown, path: string) => Result<T>): Schema<T> {
  return {
    parse,
    optional: () => makeSchema<T | undefined>((input, path) => (input === undefined || input === "" ? ok(undefined) : parse(input, path))),
  };
}

const s = {
  string: (opts: { min?: number; max?: number; pattern?: RegExp; message?: string } = {}) =>
    makeSchema<string>((input, path) => {
      if (typeof input !== "string") return fail(`${path} must be text`);
      const v = input.trim();
      if (opts.min !== undefined && v.length < opts.min) return fail(`${path} needs at least ${opts.min} characters`);
      if (opts.max !== undefined && v.length > opts.max) return fail(`${path} allows at most ${opts.max} characters`);
      if (opts.pattern && !opts.pattern.test(v)) return fail(opts.message ?? `${path} has the wrong format`);
      return ok(v);
    }),

  number: (opts: { min?: number; max?: number; int?: boolean } = {}) =>
    makeSchema<number>((input, path) => {
      const n = typeof input === "string" && input.trim() !== "" ? Number(input) : input;
      if (typeof n !== "number" || Number.isNaN(n)) return fail(`${path} must be a number`);
      if (opts.int && !Number.isInteger(n)) return fail(`${path} must be a whole number`);
      if (opts.min !== undefined && n < opts.min) return fail(`${path} must be at least ${opts.min}`);
      if (opts.max !== undefined && n > opts.max) return fail(`${path} must be at most ${opts.max}`);
      return ok(n);
    }),

  boolean: () =>
    makeSchema<boolean>((input, path) => {
      if (typeof input === "boolean") return ok(input);
      if (input === "on" || input === "true") return ok(true);
      if (input === undefined || input === "false") return ok(false);
      return fail(`${path} must be true or false`);
    }),

  enum: <const V extends readonly string[]>(values: V) =>
    makeSchema<V[number]>((input, path) =>
      typeof input === "string" && (values as readonly string[]).includes(input)
        ? ok(input as V[number])
        : fail(`${path} must be one of ${values.join(", ")}`)),

  object: <Shape extends Record<string, Schema<unknown>>>(shape: Shape) =>
    makeSchema<{ [K in keyof Shape]: Infer<Shape[K]> }>((input, path) => {
      if (typeof input !== "object" || input === null) return fail(`${path || "value"} must be an object`);
      const source = input as Record<string, unknown>;
      const out: Record<string, unknown> = {};
      const errors: string[] = [];
      for (const key of Object.keys(shape)) {
        const r = shape[key].parse(source[key], key);
        if (r.ok) out[key] = r.value;
        else errors.push(...r.errors);
      }
      return errors.length ? { ok: false, errors } : ok(out as { [K in keyof Shape]: Infer<Shape[K]> });
    }),
};

How the code works

  • type Infer<S> = S extends Schema<infer T> ? T : never Reads the "valid data" type out of any schema. This one line is what makes the whole library feel magical.
  • fail(): Result<never> A failure has no value, and never fits every Result<T>, so one helper serves all schemas.
  • { [K in keyof Shape]: Infer<Shape[K]> } A mapped type: for each field in the shape, the type of data that field's schema accepts.
  • <const V extends readonly string[]> in enum A const type parameter keeps ["free", "pro", "team"] as literal types, so plan becomes "free" | "pro" | "team", not string.
  • parse(input: unknown, …) Validators accept unknown because input really can be anything; only code that checks it may produce a typed value.
  • errors.push(...r.errors) Every field is checked even after one fails, so a user sees all their mistakes at once.

Ideas to extend it

  • Add s.array(itemSchema) returning Schema<T[]>.
  • Return errors as Partial<Record<keyof Shape, string>> to show them next to each field.
  • Add .refine(check, message) for cross-field rules like "passwords match".

  const fresh = (mode: Mode, completed: number): TimerState => ({ mode, status: "idle", remaining: DURATIONS[mode], completed });

  function transition(state: TimerState, event: TimerEvent): TimerState {
    switch (event.type) {
      case "toggle": return { ...state, status: state.status === "running" ? "paused" : "running" };

How the code works

  • transition(state, event) The entire timer's behavior in one pure function. The page never decides "what happens next"; it only asks. That's why step 2 could test it with no page.
  • $<T extends Element>(selector) One helper finds an element and gives it the right type, failing loudly if the HTML and script disagree.
  • SVGCircleElement and ring.r.baseVal.value The DOM types know SVG too: the radius is read from the circle itself to compute the circumference.
  • strokeDashoffset The ring is one long dash the length of the circle; shifting it by the elapsed fraction draws progress.
  • elapsed = (now - lastTick) / 1000 Ticks use real elapsed time, not "250 ms passed", so the timer stays accurate even when the browser delays a callback.
  • if (mode === "focus" || …) dataset.mode is string | undefined; checking each allowed value narrows it to Mode without a cast.
