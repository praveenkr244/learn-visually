Where Strings live

Most tricky String questions come down to one thing: which object does this variable point at?

Q1What is a String in Java?

A String is an object of the final class java.lang.String, not a primitive. It represents a fixed sequence of characters. The variable holds only an address, and the characters sit in a byte[] inside the object.

Try it: 2 runnable examples

class Main {
    public static void main(String[] args) {
        String name = "java";
        System.out.println(name.length());          // 4
        System.out.println(name.charAt(0));         // j
        System.out.println(name.toUpperCase());     // JAVA
        System.out.println(name instanceof Object); // true: String is a class
        System.out.println(name.getClass().getName());
    }
}
import java.util.Arrays;

class Main {
    public static void main(String[] args) {
        String s = "java";
        char[] chars = s.toCharArray();       // a copy, not the internal array
        byte[] bytes = s.getBytes();          // encoded with the default charset
        System.out.println(Arrays.toString(chars)); // [j, a, v, a]
        System.out.println(Arrays.toString(bytes)); // [106, 97, 118, 97]

        chars[0] = 'J';                       // changing the copy...
        System.out.println(s);                // ...leaves the String alone: java
        System.out.println(new String(chars));// Java
    }
}

Q2What is the String Constant Pool?

The pool is a table of shared Strings kept inside the heap (it moved out of PermGen in Java 7). When a literal is used, the JVM looks for equal text in the pool. If it finds one, it reuses that object. If not, it adds one. This saves memory because identical literals become one object.

Try it: 2 runnable examples

class Main {
    public static void main(String[] args) {
        String a = "pool";
        String b = "pool";
        String c = "po" + "ol";          // folded to "pool" by the compiler
        System.out.println(a == b);      // true: same pooled object
        System.out.println(a == c);      // true: also from the pool
        System.out.println(System.identityHashCode(a) == System.identityHashCode(b));
    }
}
class Main {
    static String fromHelper() { return "shared"; }

    public static void main(String[] args) {
        String here = "shared";
        String there = fromHelper();
        // The pool is global, so both literals resolve to the same object
        System.out.println(here == there);   // true

        String built = new StringBuilder("sha").append("red").toString();
        System.out.println(here == built);   // false: built at run time
        System.out.println(here.equals(built)); // true
    }
}

Q3How many objects does new String("java") create?

Two String objects the first time, one after that. The literal "java" needs a pool entry if it isn't there yet, and new always creates one more object on the heap. The new object shares the literal's byte[] instead of copying it.

Try it: 2 runnable examples

class Main {
    public static void main(String[] args) {
        String lit = "java";
        String n1 = new String("java");
        String n2 = new String("java");
        System.out.println(lit == n1);   // false
        System.out.println(n1 == n2);    // false: each new is a fresh object
        System.out.println(n1.equals(n2)); // true
        System.out.println(n1.intern() == lit); // true: the pooled one
    }
}
class Main {
    public static void main(String[] args) {
        char[] letters = {'j', 'a', 'v', 'a'};
        String s1 = new String(letters);     // one heap object, no literal involved
        String s2 = String.valueOf(letters); // also a new heap object
        System.out.println(s1);              // java
        System.out.println(s1 == s2);        // false
        System.out.println(s1 == "java");    // false: not the pooled literal
        System.out.println(s1.intern() == "java"); // true
    }
}

Q4What is the difference between == and equals()?

== compares addresses, so it asks whether both variables point at the same object. equals() compares content. Use equals() for Strings, every time.

Try it: 2 runnable examples

import java.util.Scanner;

class Main {
    public static void main(String[] args) {
        // Text read at run time is never the pooled literal
        String input = new Scanner("yes\n").nextLine();
        System.out.println(input == "yes");       // false
        System.out.println(input.equals("yes"));  // true
        System.out.println("yes".equals(input));  // true, and safe if input is null
    }
}
import java.util.Objects;

class Main {
    public static void main(String[] args) {
        String a = "Java", b = "JAVA", n = null;
        System.out.println(a.equals(b));             // false
        System.out.println(a.equalsIgnoreCase(b));   // true
        System.out.println(Objects.equals(n, a));    // false, no exception
        System.out.println(Objects.equals(n, null)); // true
        try {
            n.equals(a);
        } catch (NullPointerException e) {
            System.out.println("n.equals(a) throws NullPointerException");
        }
    }
}

Q5What does intern() do?

It returns the pool's copy of the text. If the pool has no such entry, Java 7 and later record a reference to the current object in the pool and return that same object.

Try it: 2 runnable examples

class Main {
    public static void main(String[] args) {
        String part = "ja";
        String runtime = part + "va";        // new heap object
        System.out.println(runtime == "java");          // false
        System.out.println(runtime.intern() == "java"); // true
    }
}
import java.util.*;

class Main {
    public static void main(String[] args) {
        String[] raw = "red,green,red,blue,red".split(",");
        // split() makes a new String for every piece
        System.out.println(raw[0] == raw[2]);   // false

        for (int i = 0; i < raw.length; i++) raw[i] = raw[i].intern();
        System.out.println(raw[0] == raw[2]);   // true: one shared object
        Set<String> ids = Collections.newSetFromMap(new IdentityHashMap<>());
        ids.addAll(Arrays.asList(raw));
        System.out.println("distinct objects: " + ids.size()); // 3
    }
}

Immutability

Once created, a String object's characters can never change.

Q6What does immutable mean?

Methods such as concat, replace and toUpperCase leave the original alone and return a new String. If you ignore the return value, the work is lost. The variable can still be reassigned, because the variable is separate from the object.

Try it: 2 runnable examples

class Main {
    public static void main(String[] args) {
        String s = "  Java  ";
        s.trim();
        s.toUpperCase();
        System.out.println("[" + s + "]");  // [  Java  ]: unchanged

        String t = s.trim().toUpperCase();   // keep the result
        System.out.println("[" + t + "]");  // [JAVA]
    }
}
class Main {
    public static void main(String[] args) {
        String s = "cat";
        String alias = s;           // both point at "cat"
        s = s.replace('c', 'b');    // s now points at a new "bat"
        System.out.println(s);      // bat
        System.out.println(alias);  // cat: the original object never changed
        System.out.println(s == alias); // false
    }
}

Q7Why is String immutable?

The pool depends on it. Many variables share one object, so a change through one would reach all of them. This imaginary example shows what would go wrong.

Safe sharing
The pool can give one object to the whole program.
Security
A file path or URL can't be changed after it passes a permission check.
Stable hash keys
The hash stays valid, so HashMap lookups keep working.
Thread safety
Threads can read the same String with no locking.

Try it: 2 runnable examples

class Main {
    public static void main(String[] args) {
        String path = "/home/user";
        String copy = path;
        path = path + "/../root";        // only path moves
        System.out.println(copy);        // /home/user

        StringBuilder sb = new StringBuilder("/home/user");
        StringBuilder sbCopy = sb;
        sb.append("/../root");           // the shared object changes
        System.out.println(sbCopy);      // /home/user/../root
    }
}
import java.util.*;

class Main {
    public static void main(String[] args) {
        Map<String, Integer> byString = new HashMap<>();
        String key = "alice";
        byString.put(key, 30);
        System.out.println(byString.get("alice"));   // 30: key can't change

        Map<StringBuilder, Integer> byBuilder = new HashMap<>();
        StringBuilder mutable = new StringBuilder("alice");
        byBuilder.put(mutable, 30);
        mutable.append("!");                          // key mutated after put
        System.out.println(byBuilder.get(new StringBuilder("alice"))); // null
    }
}

Q8How is hashCode() calculated, and why is it cached?

The formula is s[0]×31n-1 + s[1]×31n-2 + … + s[n-1], in 32-bit int arithmetic that wraps on overflow. Because the text can't change, the result is saved in the hash field. Later calls return it without looping. Type below to run the same calculation.

Try it: 2 runnable examples

class Main {
    static int myHash(String s) {
        int h = 0;
        for (int i = 0; i < s.length(); i++) h = 31 * h + s.charAt(i);
        return h;
    }
    public static void main(String[] args) {
        for (String s : new String[]{"Java", "a", "", "hello world"}) {
            System.out.println(s + " -> " + myHash(s) + " / " + s.hashCode());
        }
    }
}
class Main {
    public static void main(String[] args) {
        // Different text can share a hash: equals() still tells them apart
        System.out.println("Aa".hashCode() + " " + "BB".hashCode()); // 2112 2112
        System.out.println("Aa".equals("BB"));                       // false

        // Long strings overflow int, so the hash can be negative
        System.out.println("polygenelubricants".hashCode()); // Integer.MIN_VALUE
        System.out.println(Integer.MIN_VALUE);
    }
}

Concatenation and builders

The compiler joins what it can. Everything else happens at run time and costs a new object.

Q9Is "hel" + "lo" the same as y + "lo"?

No. Two literals form a constant expression, so the compiler writes a single "hello" into the class file. A plain variable's value is only known at run time, so the result is a new heap object outside the pool. Marking the variable final and setting it to a constant makes it a compile-time constant again.

Try it: 2 runnable examples

class Main {
    public static void main(String[] args) {
        String hello = "hello";
        String y = "hel";
        final String fy = "hel";

        System.out.println(hello == "hel" + "lo"); // true: folded
        System.out.println(hello == y + "lo");     // false: run time
        System.out.println(hello == fy + "lo");    // true: final constant
        System.out.println(hello == (y + "lo").intern()); // true
    }
}
class Main {
    static final String PREFIX = "user_";
    static final int ID = 42;
    static String dynamicPrefix = "user_";

    public static void main(String[] args) {
        System.out.println((PREFIX + ID) == "user_42");        // true: all constants
        System.out.println((dynamicPrefix + ID) == "user_42"); // false: not final
        System.out.println((dynamicPrefix + ID).equals("user_42")); // true
    }
}

Q10Why avoid += on a String inside a loop?

Each pass allocates a new String and copies every character so far, and the previous String becomes garbage. Total copying grows with the square of the length. StringBuilder appends into one array, so its cost grows in line with the length.

Q11How does StringBuilder grow?

It starts with room for 16 characters. When an append doesn't fit, it allocates a larger array, normally (old × 2) + 2, and copies the contents across. If you know the final size, new StringBuilder(1000) avoids these copies.

Try it: 2 runnable examples

class Main {
    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder();
        int last = sb.capacity();
        System.out.println("start capacity " + last);    // 16
        for (int i = 0; i < 100; i++) {
            sb.append('x');
            if (sb.capacity() != last) {
                last = sb.capacity();
                System.out.println("length " + sb.length() + " -> capacity " + last);
            }
        }
    }
}
class Main {
    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder(64);   // no regrowth needed
        sb.append("Hello").append(' ').append("World");
        sb.insert(0, ">> ");
        sb.replace(3, 8, "Howdy");
        sb.setCharAt(sb.length() - 1, 'D');
        sb.deleteCharAt(sb.length() - 2);
        System.out.println(sb);                     // >> Howdy WorD
        System.out.println(sb.length() + " / " + sb.capacity());
        System.out.println(sb.reverse());
    }
}

Q13What are Compact Strings?

Since Java 9, a String stores one byte per character when all its characters fit in LATIN1, and two bytes per UTF-16 unit otherwise. The coder field records which. English-heavy text uses about half the memory it did with char[]. Try the samples, including the emoji: length() counts UTF-16 units, so one emoji has length 2.

length() bytes stored

Bytes are shown most significant first. The order in memory follows the platform.

Try it: 2 runnable examples

class Main {
    static boolean latin1(String s) {
        return s.chars().allMatch(c -> c <= 0xFF);
    }
    public static void main(String[] args) {
        for (String s : new String[]{"Java", "café", "हिन्दी", "😀"}) {
            System.out.printf("%-8s length=%d latin1=%b stored≈%d bytes%n",
                s, s.length(), latin1(s), latin1(s) ? s.length() : s.length() * 2);
        }
    }
}
class Main {
    public static void main(String[] args) {
        String s = "hi😀";
        System.out.println(s.length());                       // 4: UTF-16 units
        System.out.println(s.codePointCount(0, s.length()));  // 3: real characters
        s.codePoints().forEach(cp ->
            System.out.println(Character.toChars(cp).length + " unit(s): U+" + Integer.toHexString(cp).toUpperCase()));
    }
}

Q14Does substring() share the original array?

Not since Java 7 update 6. It copies the selected range into a new array, so a short substring no longer keeps a huge parent String alive. Earlier versions shared the array, which caused memory leaks. The cost today is an extra copy.

Try it: 2 runnable examples

class Main {
    public static void main(String[] args) {
        String big = "x".repeat(1_000_000) + "needle";
        String small = big.substring(big.length() - 6);
        big = null;                    // the 1 MB parent can now be collected
        System.out.println(small);     // needle
        System.out.println(small.length());
    }
}
class Main {
    public static void main(String[] args) {
        String s = "interview";
        System.out.println(s.substring(5));       // view
        System.out.println(s.substring(0, 5));    // inter (end is exclusive)
        System.out.println(s.substring(3, 3).isEmpty()); // true
        System.out.println(s.substring(0) == s);  // true: whole string is reused
        try {
            s.substring(4, 2);
        } catch (StringIndexOutOfBoundsException e) {
            System.out.println("begin > end: " + e.getMessage());
        }
    }
}

Q15Why is char[] preferred over String for passwords?

You can overwrite an array the moment you finish with it. A String can't be wiped, so the secret stays in memory until the garbage collector reclaims and overwrites that space, and it could appear in a heap dump. Printing an array by accident also shows a type and address, while printing a String shows the secret.

Try it: 2 runnable examples

import java.util.Arrays;

class Main {
    static boolean check(char[] pw) {
        return Arrays.equals(pw, "s3cret".toCharArray());
    }
    public static void main(String[] args) {
        char[] pw = {'s', '3', 'c', 'r', 'e', 't'};
        System.out.println("valid: " + check(pw));
        Arrays.fill(pw, '*');                        // wipe it straight away
        System.out.println("after wipe: " + new String(pw)); // ******
    }
}
class Main {
    public static void main(String[] args) {
        String pwString = "hunter2";
        char[] pwChars = "hunter2".toCharArray();
        System.out.println("log: " + pwString); // log: hunter2   (leaked)
        System.out.println("log: " + pwChars);  // log: [C@...    (type and hash)
    }
}

Q16Reverse a String without reverse()

Copy it to a char[], then swap from both ends towards the middle. This takes O(n) time. In real code, use new StringBuilder(s).reverse().toString(), which also keeps emoji intact.

Try it: 2 runnable examples

class Main {
    static String reverse(String s) {
        char[] c = s.toCharArray();
        for (int i = 0, j = c.length - 1; i < j; i++, j--) {
            char t = c[i]; c[i] = c[j]; c[j] = t;
        }
        return new String(c);
    }
    public static void main(String[] args) {
        for (String s : new String[]{"string", "a", "", "racecar"}) {
            System.out.println("\"" + s + "\" -> \"" + reverse(s) + "\"");
        }
    }
}

Q17Check whether a String is a palindrome

Compare from both ends and stop at the first mismatch. This takes O(n) time and needs no extra array. Try racecar and rotator, then a word that fails.

Try it: 2 runnable examples

class Main {
    static boolean isPalindrome(String s) {
        for (int i = 0, j = s.length() - 1; i < j; i++, j--) {
            if (s.charAt(i) != s.charAt(j)) return false;
        }
        return true;
    }
    public static void main(String[] args) {
        for (String s : new String[]{"madam", "racecar", "rotator", "java", "a"}) {
            System.out.println(s + " -> " + isPalindrome(s));
        }
    }
}
class Main {
    static boolean isPalindrome(String s) {
        int i = 0, j = s.length() - 1;
        while (i < j) {
            char a = s.charAt(i), b = s.charAt(j);
            if (!Character.isLetterOrDigit(a)) { i++; continue; }
            if (!Character.isLetterOrDigit(b)) { j--; continue; }
            if (Character.toLowerCase(a) != Character.toLowerCase(b)) return false;
            i++; j--;
        }
        return true;
    }
    public static void main(String[] args) {
        System.out.println(isPalindrome("A man, a plan, a canal: Panama")); // true
        System.out.println(isPalindrome("Was it a car or a cat I saw?"));   // true
        System.out.println(isPalindrome("race a car"));                     // false
    }
}

Q18Check whether two words are anagrams

Count letters up for the first word and down for the second. If every count ends at zero, they use the same letters. This takes O(n) time and beats sorting, which takes O(n log n). The demo keeps lowercase a to z only.

Try it: 2 runnable examples

class Main {
    static boolean isAnagram(String a, String b) {
        if (a.length() != b.length()) return false;
        int[] count = new int[26];
        for (int i = 0; i < a.length(); i++) {
            count[a.charAt(i) - 'a']++;
            count[b.charAt(i) - 'a']--;
        }
        for (int c : count) if (c != 0) return false;
        return true;
    }
    public static void main(String[] args) {
        System.out.println(isAnagram("listen", "silent")); // true
        System.out.println(isAnagram("rat", "car"));       // false
    }
}
import java.util.*;

class Main {
    public static void main(String[] args) {
        String[] words = {"eat", "tea", "tan", "ate", "nat", "bat"};
        Map<String, List<String>> groups = new TreeMap<>();
        for (String w : words) {
            char[] c = w.toCharArray();
            Arrays.sort(c);                          // sorted letters are the key
            groups.computeIfAbsent(new String(c), k -> new ArrayList<>()).add(w);
        }
        groups.forEach((key, list) -> System.out.println(key + " -> " + list));

Quick answers

Can you extend String?
No. The class is final.
length or length()?
Arrays have a length field. String has a length() method.
isEmpty() or isBlank()?
isEmpty() means length 0. isBlank() (Java 11) is also true for whitespace only.
trim() or strip()?
trim() removes characters up to U+0020. strip() (Java 11) understands Unicode whitespace.
What does compareTo() return?
The difference at the first mismatch. "apple".compareTo("apricot") gives 'p' - 'r', which is -2.
How do I compare safely with null?
Write "java".equals(s) or Objects.equals(a, b). Neither throws.
How does switch work on a String?
Since Java 7, it compiles to a hashCode() switch followed by equals().
Is String a good HashMap key?
Yes. It is immutable, has a correct equals(), and caches its hash.
