Getting started

JavaScript is the language of the web. Every browser runs it, and with Node.js it also runs servers, command-line tools and build scripts. You write plain text (in a .js file or a <script> tag) and a JavaScript engine runs it.

Where JavaScript runs

  1. In this page. Press Run on any block. Console examples run in a background worker; page examples run in a small sandboxed preview.
  2. In any browser. Open the developer tools (F12, or ⌥⌘I on a Mac), choose the Console tab and type 2 + 3.
  3. With Node.js. Install the LTS version from nodejs.org, save code in hello.js and run node hello.js. Type node alone for an interactive prompt.
  4. In a web page. Put <script src="app.js" defer></script> in your HTML.

Rules of the road

JavaScript is case-sensitive (Name ≠ name). Statements end with a semicolon ;. The engine can insert missing ones, but writing them avoids rare surprises. Strings use "double", 'single' or `backtick` quotes.

Variables: let, const and references

A variable is a name for a value. Declare it with const when the name will always point at the same value, or let when you will reassign it. The old var still works but has confusing scoping rules, so avoid it.

let age = 30;          // can be reassigned
const name = "Ada";    // cannot be reassigned
age = age + 1;
console.log(name, age);

// const means "this name always points here", not "frozen":
const scores = [90, 85];
scores.push(70);       // fine: we changed the array, not the name
console.log(scores);

try {
  name = "Grace";      // TypeError: Assignment to constant variable
} catch (e) {
  console.log("Error:", e.message);
}

Types of values

JavaScript has seven primitive types (number, string, boolean, undefined, null, bigint, symbol) and one structural type: object, which includes arrays, functions, dates and everything else. Variables don't have types; values do.

console.log(typeof 42);          // number (integers and decimals share one type)
console.log(typeof 3.14);        // number
console.log(typeof "hi");        // string
console.log(typeof true);        // boolean
console.log(typeof undefined);   // undefined: "no value assigned yet"
console.log(typeof null);        // object  ← a famous historical bug!
console.log(typeof 10n);         // bigint: whole numbers of any size
console.log(typeof Symbol("id"));// symbol: a unique key
console.log(typeof {});          // object
console.log(typeof []);          // object (use Array.isArray to check)
console.log(typeof function () {}); // function (a callable object)
console.log(Array.isArray([]));  // true
undefined vs null

undefined means a value was never set: a missing property, a parameter nobody passed. null means "intentionally empty", set by you.

Numbers are floating point

0.1 + 0.2 is 0.30000000000000004. Round for display with toFixed(2), and count money in cents.

// Converting between types

console.log(parseInt("42px"), parseFloat("3.5kg"));        // 42 3.5
console.log(String(99), (99).toString(2));                 // "99" "1100011"
console.log(Boolean(""), Boolean("0"), Boolean(0));        // false true false

// NaN ("not a number") is a number that is not equal to itself
console.log(NaN === NaN, Number.isNaN(Number("abc")));
console.log(0.1 + 0.2, (0.1 + 0.2).toFixed(2));
console.log(Number.MAX_SAFE_INTEGER, 2n ** 64n);

Operators, equality and coercion

Operators combine values: arithmetic (+ - * / % **), comparison (=== !== < >) and logic (&& || ! ??). JavaScript sometimes coerces (silently converts) values to make an operator work, which is why you should always compare with ===.

console.log(7 / 2, 7 % 2, 2 ** 10);   // 3.5 1 1024
console.log(Math.floor(7 / 2), Math.round(2.5), Math.max(3, 9, 4));

// + joins strings; the other math operators convert to numbers
console.log("3" + 4, "3" - 1, "3" * "4");   // "34" 2 12

// === checks type AND value; == converts first (avoid it)
console.log(1 === "1", 1 == "1");           // false true
console.log(0 == "", null == undefined);    // true true

let count = 5;
count += 2; count *= 3; count++;
console.log(count);                          // 22

Logical operators return values, not just true/false

// || returns the first truthy value: handy for defaults
console.log("" || "guest");        // "guest"
console.log(0 || 10);              // 10  ← 0 is falsy, maybe not what you wanted!

// ?? (nullish coalescing) only falls back on null or undefined
console.log(0 ?? 10);              // 0
console.log(null ?? "default");    // "default"

// && returns the first falsy value (or the last value)
const user = { name: "Ada", address: null };
console.log(user && user.name);    // "Ada"

// ?. (optional chaining) stops at null/undefined instead of throwing
console.log(user.address?.city);   // undefined, no error
console.log(user.getName?.());     // undefined: the method doesn't exist

  2. When does a ?? b differ from a || b? — When a is falsy but not null/undefined, e.g. 0 or "": ?? keeps a.

A string is an immutable sequence of characters. String methods never change the original: they return a new string. Template literals (backticks) let you embed any expression with ${…} and span several lines.

console.log("a,b,c".split(","), ["x", "y"].join(" + "));
console.log("ha".repeat(3), "7".padStart(3, "0"));
console.log("cat dog cat".replaceAll("cat", "🐱"));

Making decisions

if runs a block only when its condition is truthy. Chain alternatives with else if, catch everything else with else, choose between many exact values with switch, and pick between two values inline with the ternary cond ? a : b.

const temp = 22;
if (temp > 30) {
  console.log("hot");
} else if (temp > 15) {
  console.log("pleasant");
} else {
  console.log("cold");
}

// Ternary: an if/else that produces a value
const label = temp >= 18 ? "T-shirt" : "Jacket";
console.log(label);
// switch compares with === and falls through until break
function dayType(day) {
  switch (day) {
    case "Sat":
    case "Sun":
      return "weekend";
    case "Fri":
      return "almost weekend";
    default:
      return "weekday";
  }
}
console.log(dayType("Sun"), dayType("Fri"), dayType("Tue"));
Guard clauses

Instead of deep nesting, return early when something is wrong: if (!user) return;. The rest of the function then handles only the normal case.

Loops

Loops repeat a block. Use for…of to visit each item of an array or string, the classic for (let i = 0; …) when you need the index or a custom step, while when you don't know in advance how many times, and for…in for the keys of an object.

const fruits = ["apple", "banana", "cherry"];

for (const fruit of fruits) console.log(fruit);            // values

for (let i = 0; i < fruits.length; i++) {                  // indexes
  console.log(i, fruits[i]);
}

for (const [i, fruit] of fruits.entries()) console.log(`${i + 1}. ${fruit}`);

const scores = { ada: 95, linus: 88 };
for (const key in scores) console.log(key, "→", scores[key]); // object keys
// while: repeat until a condition becomes false
let n = 27, steps = 0;
while (n !== 1) {
  n = n % 2 === 0 ? n / 2 : 3 * n + 1;   // the Collatz sequence
  steps++;
}
console.log("steps:", steps);

// break leaves the loop; continue skips to the next round
for (let i = 1; i <= 10; i++) {
  if (i % 2 === 0) continue;
  if (i > 7) break;
  console.log("odd:", i);
}
for…in on arrays

for…in gives keys as strings and also visits inherited properties. Use for…of (or array methods) for arrays.

Arrays

An array is an ordered list. Items are numbered from 0, can be any type, and the list grows and shrinks as you add or remove items. Some methods change the array (push, pop, splice, sort); others return a new one (slice, concat, toSorted).

const nums = [5, 2, 9];
nums.push(7);              // add to the end     → [5, 2, 9, 7]
nums.unshift(1);           // add to the start   → [1, 5, 2, 9, 7]
const last = nums.pop();   // remove from end    → 7
const first = nums.shift();// remove from start  → 1
console.log(nums, last, first);

console.log(nums.length, nums[0], nums.at(-1));
console.log(nums.includes(9), nums.indexOf(2));

nums.splice(1, 1, 20, 30); // at index 1: remove 1 item, insert 20 and 30
console.log(nums);
console.log(nums.slice(1, 3), nums);   // slice copies a part, nums unchanged
// Sorting: the default sort compares as STRINGS
const values = [10, 1, 5, 100];
console.log([...values].sort());                 // [1, 10, 100, 5] !
console.log([...values].sort((a, b) => a - b));  // numeric ascending
console.log(values.toSorted((a, b) => b - a));   // new array, descending
console.log(values);                             // unchanged

// Build arrays
console.log(Array.from({ length: 5 }, (_, i) => i * i));
console.log([..."hello"], [1, 2].concat([3], [4, 5]));
console.log([[1, 2], [3, [4]]].flat(Infinity));
Check yourself

Functions

A function is a reusable block of code with a name, inputs (parameters) and an output (its return value). In JavaScript functions are values: you can store them in variables, pass them to other functions and return them.

// 1. Function declaration (hoisted: usable before this line)
function add(a, b) {
  return a + b;
}

// 2. Function expression
const multiply = function (a, b) {
  return a * b;
};

// 3. Arrow function: short, and the body can be a single expression
const square = x => x * x;
const greet = (name = "friend") => `Hello, ${name}!`;   // default parameter

console.log(add(2, 3), multiply(4, 5), square(9));
console.log(greet(), greet("Ada"));

// Rest parameters collect any number of arguments into an array
function sum(...nums) {
  return nums.reduce((total, n) => total + n, 0);
}
console.log(sum(1, 2, 3, 4), sum());

// A function without return gives undefined
function shout(s) { console.log(s.toUpperCase()); }
console.log(shout("hey"));
// Functions are values: pass them around
const ops = { add: (a, b) => a + b, sub: (a, b) => a - b };
function apply(op, a, b) { return ops[op](a, b); }
console.log(apply("add", 10, 4), apply("sub", 10, 4));

// A function that returns a function
const makeGreeter = greeting => name => `${greeting}, ${name}!`;
const hello = makeGreeter("Hello");
console.log(hello("Ada"), makeGreeter("Hola")("Linus"));

Scope and hoisting

Scope decides where a name is visible. let and const are visible only inside the nearest { } block. When code uses a name, JavaScript looks in the current scope, then the enclosing one, and so on outward to the global scope. That path is the scope chain.

const appName = "Todo";            // global (module) scope

function render() {
  const title = "My list";         // function scope
  if (true) {
    const count = 3;               // block scope
    console.log(appName, title, count);   // all visible here
  }
  try {
    console.log(count);            // not visible outside its block
  } catch (e) {
    console.log("ReferenceError:", e.message);
  }
}
render();

Hoisting and the temporal dead zone

// Function declarations are hoisted completely
console.log(double(4));
function double(n) { return n * 2; }

// var is hoisted but starts as undefined (confusing!)
console.log(legacy);   // undefined
var legacy = "old";

// let/const exist from the start of the block but can't be used
// before their line: the "temporal dead zone"
try {
  console.log(modern);
} catch (e) {
  console.log(e.name + ":", e.message);
}
let modern = "new";

Errors and try…catch

When something goes wrong, JavaScript throws an error object. If nothing catches it, the program stops. Wrap risky code in try, handle the problem in catch, and put cleanup that must always run in finally.

function parseAge(text) {
  const age = Number(text);
  if (Number.isNaN(age)) throw new TypeError(`"${text}" is not a number`);
  if (age < 0 || age > 150) throw new RangeError(`${age} is out of range`);
  return age;
}

for (const input of ["42", "abc", "-5"]) {
  try {
    console.log("age:", parseAge(input));
  } catch (err) {
    console.log(`${err.name}: ${err.message}`);
  } finally {
    console.log("  checked", JSON.stringify(input));
  }
}

Classes

A class is a blueprint for objects that share the same shape and behavior. The constructor sets up each new instance; methods are shared by all instances. Use extends to build a specialised class on top of another, and #private fields for data no outside code may touch.

What is this?

this is decided when a function is called, not where it is written. Called as obj.method(), this is obj. Called on its own, it is undefined (in modern strict code). Arrow functions have no this of their own: they use the one from the surrounding code.

  name: "Ada",
  regular() { return this?.name; },
  arrow: () => typeof this,          // takes this from outside the object

  },
};

Iterators and generators

Anything you can use in for…of or spread with ... is iterable: arrays, strings, Maps, Sets. A generator function (function*) is the easy way to make your own: each yield hands out one value and pauses the function until the next value is asked for.

function* countdown(n) {
  while (n > 0) {
    yield n;          // pause here and hand n to the caller
    n--;
  }
  return "liftoff";   // the final value (not part of for…of)
}

const gen = countdown(3);
console.log(gen.next());   // { value: 3, done: false }
console.log(gen.next());
console.log(gen.next());
console.log(gen.next());   // { value: 'liftoff', done: true }

console.log([...countdown(5)]);
for (const n of countdown(2)) console.log("T-minus", n);
// Infinite sequences are fine: values are made only on demand
function* naturals() { let n = 1; while (true) yield n++; }
function* take(iterable, count) {
  for (const x of iterable) {
    if (count-- <= 0) return;
    yield x;
  }
}
function* mapIt(iterable, fn) { for (const x of iterable) yield fn(x); }

console.log([...take(mapIt(naturals(), n => n * n), 6)]);

// Make a class iterable with Symbol.iterator
class Range {
  constructor(from, to, step = 1) { Object.assign(this, { from, to, step }); }
  *[Symbol.iterator]() { for (let i = this.from; i <= this.to; i += this.step) yield i; }
}

The event loop

JavaScript runs your code on one thread: one thing at a time. Slow work (timers, network, clicks) is handed to the browser or Node.js, and when it finishes a callback is put in a queue. The event loop runs a callback from a queue only when the call stack is empty, and it always empties the microtask queue (promise callbacks) before taking the next task (timers, events).

console.log("A: script starts");

setTimeout(() => console.log("B: timeout callback (task)"), 0);

Promise.resolve().then(() => console.log("C: promise callback (microtask)"));

queueMicrotask(() => console.log("C2: another microtask"));

console.log("D: script ends");
// Long synchronous work blocks everything else, timers included
const start = performance.now();
setTimeout(() => console.log(`timer ran after ${Math.round(performance.now() - start)} ms (asked for 10)`), 10);

let x = 0;
while (performance.now() - start < 300) x++;   // busy for 300 ms
console.log("busy loop done");

Promises

A promise is an object standing for a value that will arrive later. It starts pending, then becomes fulfilled with a value or rejected with an error, and never changes again. You attach what to do next with .then, handle errors with .catch and clean up with .finally.

// Create a promise: call resolve or reject when the work is done
function wait(ms, value) {
  return new Promise(resolve => setTimeout(() => resolve(value), ms));
}
function mayFail(ok) {
  return new Promise((resolve, reject) =>
    setTimeout(() => (ok ? resolve("worked") : reject(new Error("failed"))), 100));
}

wait(200, 21)
  .then(n => n * 2)                     // each then returns a new promise
  .then(n => console.log("result:", n))
  .finally(() => console.log("cleanup runs either way"));

mayFail(false)
  .then(v => console.log("never runs", v))
  .catch(err => console.log("caught:", err.message));

Running several at once

const wait = (ms, v) => new Promise(r => setTimeout(() => r(v), ms));
const fail = (ms, msg) => new Promise((_, rej) => setTimeout(() => rej(new Error(msg)), ms));

// all: every promise must fulfil (fails fast on the first rejection)
Promise.all([wait(100, "a"), wait(300, "b"), wait(200, "c")]).then(v => console.log("all:", v));

// allSettled: wait for everything and report each outcome
Promise.allSettled([wait(50, "ok"), fail(80, "boom")]).then(r => console.log("allSettled:", r));

// race: the first to settle wins; any: the first to FULFIL wins
Promise.race([wait(150, "slow"), wait(60, "fast")]).then(v => console.log("race:", v));
Promise.any([fail(30, "x"), wait(90, "first success")]).then(v => console.log("any:", v));
Always handle rejections

A rejected promise with no .catch becomes an "unhandled rejection" error. End every chain with .catch, or use try/catch with await.

async and await

An async function always returns a promise. Inside it, await pauses that function (not the whole program) until a promise settles, so asynchronous code reads top to bottom like normal code, and errors are caught with ordinary try/catch.

const wait = ms => new Promise(r => setTimeout(r, ms));

async function download(name, ms) {
  await wait(ms);
  return `${name} (${ms} ms)`;
}

async function sequential() {
  console.time("sequential");
  const a = await download("A", 200);   // wait…
  const b = await download("B", 100);   // …then wait again
  const c = await download("C", 300);
  console.timeEnd("sequential");
  return [a, b, c];
}

async function parallel() {
  console.time("parallel");
  const all = await Promise.all([download("A", 200), download("B", 100), download("C", 300)]);
  console.timeEnd("parallel");
  return all;
}

Useful patterns: debounce, throttle, pipelines

A few small patterns appear in almost every app. Debounce waits until calls stop (search-as-you-type). Throttle allows at most one call per interval (scroll handlers). Composition builds big functions out of small ones. Event emitters let parts of a program talk without knowing about each other.

function debounce(fn, ms) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), ms);
  };
}
function throttle(fn, ms) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= ms) { last = now; fn(...args); }
  };
}

const search = debounce(q => console.log("debounced search:", q), 100);
const onScroll = throttle(y => console.log("throttled scroll:", y), 100);

for (let i = 1; i <= typed.length; i++) {
  setTimeout(() => { search(typed.slice(0, i)); onScroll(i * 100); }, i * 30);
}

const pipe = (...fns) => input => fns.reduce((value, fn) => fn(value), input);

  s => s.trim(),

// A tiny event emitter (publish/subscribe)
function createEmitter() {
  const handlers = new Map();
  return {
    on(event, fn) {
      if (!handlers.has(event)) handlers.set(event, new Set());
      handlers.get(event).add(fn);
      return () => handlers.get(event).delete(fn);   // returns "unsubscribe"
    },
    emit(event, data) { handlers.get(event)?.forEach(fn => fn(data)); },
  };
}

How the code works

  • const $ = selector => … A two-character shortcut for document.querySelector, used everywhere below.

How the code works

  • getJSON(url) One helper owns "fetch, check res.ok, parse". Both API calls reuse it, so an HTTP error can't slip through either.
  • data.results?.length Optional chaining: if results is missing (no match) the expression is undefined, which is falsy, so we throw a friendly error instead of crashing.
  • let latest = 0 and if (id !== latest) return Requests can finish in any order. Each search remembers its number and only the newest one may touch the page.
  • err instanceof TypeError fetch rejects with a TypeError when the network fails; our own errors are plain Errors with messages meant for people.
  • finally Runs after success and failure alike, so the button can never get stuck disabled.
  • timeZone: "UTC" on the day formatter The API's dates ("2026-11-26") are parsed as UTC midnight; formatting in UTC keeps the weekday right in every time zone.

  2. Write the rules as a state machine

    handleClick(state, i) applies the rules and returns what happened: "ignore", "first", "match", "miss" or "win". After a miss the board is locked until hideMiss() flips the two cards back. Simulate a game in the console before drawing anything.

    function newGame(deck) {
  return { deck, first: null, second: null, locked: false, moves: 0 };
}

function handleClick(state, i) {
  const card = state.deck[i];
  if (state.locked || card.matched || i === state.first) return "ignore";
  if (state.first === null) { state.first = i; return "first"; }

  state.second = i;
  state.moves++;
  const other = state.deck[state.first];
  if (other.symbol === card.symbol) {
    other.matched = card.matched = true;
    state.first = state.second = null;
    return state.deck.every(c => c.matched) ? "win" : "match";
  }
  state.locked = true;                        // two wrong cards stay visible for a moment
  return "miss";
}

function hideMiss(state) {
  state.first = state.second = null;
  state.locked = false;
}

How the code works

  • return "miss" handleClick reports what happened as a word. The rules never touch the DOM, and the page never decides who matched. You could swap the page for a terminal version without changing a single rule.
  • i === state.first Clicking the same card twice is ignored, otherwise one card could "match itself".
  • state.locked = true While a wrong pair is visible, every click returns "ignore". Without the lock, fast clickers could flip a third card.
  • setTimeout(() => { hideMiss(game); render(); }, 800) Gives the player time to remember both cards before they flip back.
  • transform-style: preserve-3d and backface-visibility: hidden The two faces sit back to back; rotating the button 180° hides one and shows the other.
  • setInterval(tick, 250) The clock is computed from Date.now() - startedAt, not by counting ticks, so it stays accurate even if the tab is busy.
